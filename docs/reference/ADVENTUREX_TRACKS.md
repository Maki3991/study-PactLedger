今年，我们想干点更疯狂的 - 给你的 Agent 一副身体，怎么样？

## 14. 它写、它画、它验：无人值守的前端自进化工厂

**主办方 / 机构：** 阶跃星辰

**原表行号：** 338–368

### 赛题说明 / 背景 / 规则

AI 一分钟就能写出一个网页，但它写得对吗？按钮能点吗？配图对味吗？

今天 AI 生成前端的"最后一公里"仍然靠人眼验收：人来打开浏览器、人来点按钮、人来皱眉说"这配图不对味，再改改"。只要验收还依赖人，AI 编程就永远是半自动的——它写 1 分钟，你陪 1 小时。

而打通这一公里需要的拼图，其实都已经在桌上：多模态模型能"看懂"一张页面截图，生图模型能凭空造出页面所需的视觉素材，浏览器自动化能替人点按钮，Agent 能根据反馈改代码、重画图。缺的只是一个把它们串起来、并且能长时间无人值守运行的系统——AI 自己写、自己画、自己看、自己测、自己改。人类只在开始时提一个需求，在结束时收一个界面完整、素材原创的成品。

这就是本赛道要你造的东西：一台可以通宵干活、越干越对的前端自进化工厂。

你要做什么

构建一个 "开发 → 验证 → 迭代"的全自动闭环前端开发系统

输入一张需求卡（一段 ≤100 字的自然语言需求 + 一句参考风格描述），系统随后全程无人干预地完成：

前端生成：生成 Agent 产出网页（HTML/JS 或 React 均可）；

素材自产（生图 API）：页面所需的全部视觉素材（Logo、插画、背景图、装饰图形等）可以由自研生图 API 实时生成，或搜索得到；

多模态自验收：Verify Agent 对渲染结果截图，用多模态模型比对需求文字与风格描述，检查布局是否合理、生图素材是否切题、整页风格是否统一；同时可通过浏览器自动化（如 Playwright）实际点击按钮、填写表单，验证交互真实可用；

自迭代：验收产出结构化问题清单（布局偏差 / 素材跑题 / 风格打架 / 交互时效等），自动回流打回重改，判断是改代码还是重新生图，由系统自主判断，随后进入下一轮；

长程运行：以上循环持续稳定运行，可以是对一张难卡反复收敛，也可以是流水线式连续消化一批需求卡，期间验收通过项 / 风格匹配评分等指标应随时间可见地上升。

输入与产出

输入只有需求卡：

开赛时官方公开 8 张示例需求卡（例：「做一个带深色模式切换的番茄钟，插画要可爱一点」）；终审时评委从未公开的需求卡中抽取，现场投喂盲测。

产出三样：

最终网页成品

完整迭代轨迹（每轮的截图、生成的素材、验收结论、改动摘要）

一次 ≥1 小时无人干预运行的日志与自我核验的指标曲线

参与要求

必须有独立的 Verify Agent，且通过多模态手段验收：

截图 + 视觉模型理解是底线；对生图素材切题性/风格一致性的检查、自动化交互验证是强烈加分项。只跑 Lint、单元测试，或让生成模型"自己说自己没问题"的，不算 Self-Verify。

闭环必须无人值守：

验收结论自动触发重改（含自动重新生图），至少能连续自动运行 3 轮；严禁人工在轮次之间修改代码、提示词或素材。

必须真正长跑过：

提交一次连续 1 小时以上无人干预运行的完整日志与指标曲线，并说明你解决了长程运行经典难题中的至少两个（上下文/记忆管理、断点续跑、防目标漂移、成本控制）。

### 赛题说明 / 背景 / 规则

过去一年,所有人都在做 Agent —— 但绝大多数 Agent 被困在网页聊天框里,等着用户主动打开、主动输入。真实世界不是这样运作的:人和人之间最高频的交互发生在 iMessage、WhatsApp、Telegram、Discord 这些消息应用里。

如果 Agent 想真正进入人的生活,它需要的不是又一个网页,而是一个手机号。

Photon 的 Spectrum API 让任何 AI Agent 在几分钟内拥有自己的电话号码和消息身份,原生接入 iMessage、WhatsApp、Telegram、Discord、Slack、Signal、Teams 和 SMS/RCS 八大渠道。你的 Agent 可以主动发消息、被拉进群聊、发语音和图片、参与真实的人类对话流 —— 消息本身,就是最自然的 Agent 界面。

我们不期待:又一个套壳 chatbot 网页。我们希望你认真思考:当 Agent 拥有手机号之后,哪些交互形态第一次成为可能?
