## 1. 修复后结论

本轮已把新故事从文档目标态推进到本地代码可验证状态：

```text
@Bot 发起
  -> Bot 立即发送处理中卡片，展示 @发起人、发起时间和原始请求
  -> LLM structured output 提取商品、期望数量、单位、渠道、店铺、链接和参考价
  -> Bot 编辑同一张卡片为 COLLECTING 可认领卡片
  -> 群成员可继续认领，期望数量不再是硬容量
  -> 发起人点击 Request final quote 时按当前实际认领数量锁单
  -> 锁单参与人逐人确认，全部确认后沿用现有 Mock 支付闭环
```

重要边界不变：

- `purchaseChannelHint`、`storeNameHint`、`merchantLinkHint` 都只是用户意图，不是可信商户、收款人或金额。
- 最终 merchant、payee、amount 仍只能来自 verified Checkout。
- 当前支付闭环仍是本地 Mock；未完成远程 PactLedger Payment Base、A2A Merchant/Payment transport 或 Injective Testnet/Live 付款。
- 本轮验证是本地测试和构建验证；尚未提供真实 Telegram 群聊、公网部署和外部 Smoke Test 证据。

## 3. 关键代码证据

### 3.1 Telegram 卡片生命周期

`poolmate/backend/src/bot/grammy/handlers/poolHandlers.ts`

- `processingCardMessage()` 生成“拼单请求处理中”卡片，展示 `Started by`、`Started at`、原始请求和无 Checkout/确认/付款状态。
- `editStatusCard()` 封装 `context.api.editMessageText(...)`，失败时降级为 `context.reply(...)`。
- 自然语言 handler 在解析前立即发送处理中卡片；解析完整后调用 `useCases.createPool(...)` 并编辑同一条消息为 `COLLECTING` 认领卡片。
- 缺字段或 LLM 失败时，同一卡片更新为“需要补充信息 / 未创建订单、Checkout、确认或付款”。

### 3.2 结构化采购意图

涉及文件：

- `poolmate/shared/src/orders.ts`
- `poolmate/backend/src/application/ports/orderDraftExtractor.ts`
- `poolmate/backend/src/domain/orderIntent.ts`
- `poolmate/backend/src/infrastructure/llm/httpOrderDraftExtractor.ts`
- `poolmate/frontend/src/api/ordersApi.ts`
- `poolmate/frontend/src/orders/OrdersView.tsx`

新增字段：

```text
storeNameHint
merchantLinkHint
```

LLM structured output schema 仍为 strict，拒绝额外 payment/merchant/payee/finalAmount 字段。新增店铺和链接字段仅作为不可信 hint 保留，不参与可信 Checkout 和支付构造。

### 3.3 期望数量语义

`poolmate/backend/src/application/orderService.ts`

修复前：

```text
projected > targetUnits -> CAPACITY_EXCEEDED
projected === targetUnits -> 自动 QUOTE_PENDING
finalizeCheckout 要求 claimedUnits === targetUnits
```

修复后：

```text
projected > MAX_TOTAL_CLAIM_UNITS -> CAPACITY_EXCEEDED
认领后保持 COLLECTING
Request final quote 才把 COLLECTING 锁到 QUOTE_PENDING
finalizeCheckout 要求 claimedUnits > 0
quote totalUnits = 锁单时实际 claimedUnits
```

因此 `targetUnits` 在当前兼容字段名下承担产品语义上的“期望数量 / expected units”，不再是最大容量或支付门槛。

### 3.4 前端数据守卫

`poolmate/frontend/src/api/ordersApi.ts` 已去掉 `claimedUnits <= targetUnits` 的硬校验，避免后台真实返回 4/3 时被 UI 拒收。管理页 purchase intent 区域展示渠道、店铺和链接 hint。


新增或更新的关键测试覆盖：

- 自然语言 @mention 先发送处理中卡片，再 `editMessageText` 更新为 `COLLECTING` 卡片。
- 处理中卡片包含 `@alice` 和发起时间。
- 店铺名和链接从 LLM 输出进入 intent，并展示在卡片中。
- LLM 缺字段时编辑处理中卡片，不创建 order/checkout/payment。
- 未达期望数量可以锁单生成 Checkout。
- 超过期望数量可以锁单生成 Checkout。
- 发起人请求最终报价后，参与人 claim/leave 被锁住。
- 前端 API guard 接受 `claimedUnits > targetUnits`。
